# Mandatory video safeguards

Owner feedback,23November2026. Apply to every future episode, not only ice cream.

- Preserve accepted assets and story. Make scoped revisions without silently dropping approved subjects.
- Motion must explain: physical cause/effect, changing state, meaningful reveal or data sampled in time. Replace long plain middle holds. Generic scale/zoom is not a substitute.
- Write like a person. Remove repetitive not-X-but-Y contrasts and script scaffolding. Read the full script for these before synthesis.
- Keep only on-screen text that serves the content. Credits and source notes belong in captions/descriptions unless genuinely required on-screen.
- Let the final thought breathe. Check sentence boundaries, word pace, and a deliberate gap before the CTA. Preserve the approved full endcard from its first frame.
- Captions are immutable phrase cues, never a moving per-frame sliding token window. Every spoken token appears once. Repair overlap before grouping, never hide a clause to fix overlap.
- Run scripts/check_caption_cues.py on the source transcript and final cues. Reject duplicated/missing words, backward/overlapping cues, flashing phrases and unreadable length.
- Inspect every caption cue as pixels from the exact exported master. Inspect entrances, exits, section transitions and the CTA gap, not only a contact sheet of six arbitrary frames.
- Listen to the affected audio and inspect motion when capability exists. A transcript/timing check is not acoustic listening. Record the limitation if listening cannot be performed, never silently pass it.
- Verify factual visual semantics: closed lock for lockout, explicit measured units/threshold/deadline where a graph bears the explanation. Mark hypothetical examples through narration/context; do not present invented store records.
- Verify final encoded loudness, peak, black intervals, dimensions, duration and media hash. Upload exact approved bytes and read back the scheduled state.

The renderer, caption cues and final encode are one release candidate. Any change to any of them invalidates the relevant QA evidence. User review is not the first QA layer.
